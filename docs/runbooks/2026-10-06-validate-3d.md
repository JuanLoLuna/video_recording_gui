# Step 16: measure the real 3D accuracy

Plan: [`docs/plans/2026-10-05-sync-and-3d-calibration.md`](../plans/2026-10-05-sync-and-3d-calibration.md), step 16.
Script: [`scripts/validate_3d.py`](../../scripts/validate_3d.py).

**What this answers:** how accurately the current camera setup measures in 3D at different places in the workspace, in millimetres, from a board of known size. The board is held still, so the unsynchronised cameras do not matter.

**Time:** about 10 minutes of recording, then a few minutes for the script.

---

## 1. Record (about 5 min)

1. Start the recorder: **Detect camera**, then **Start Preview**. The status line must say **"3D pose: ready"**; run the setup and verify first if it does not.
2. **Start Recording.**
3. Put **A-big** (the setup board) at **5–6 different places** in the work area, for example:
   - where the hands work, near the panel;
   - left and right of that;
   - raised on the box;
   - tilted toward one camera, then toward the other;
   - one place away from where the setup was done (at least 15 cm). That is the honest test.

   At each place: let go, **take your hands out of view, and keep everything still for about 5 s.** Both cameras must see the whole board.
4. **Stop Recording.**

## 2. Run the script (on the rig, or anywhere with the session folder)

From the repo root, in the recorder's Python environment:

```powershell
python scripts\validate_3d.py "D:\path\to\the\recording folder"
```

If the folder holds several recordings, add `--basename recording_YYYYMMDD_HHMMSS`.

**What it does:**
- Finds every stretch of at least 2 s where both cameras see the board still.
- Triangulates the board with the session's saved setup, and compares it with the real board (same check as Verify).
- Prints one line per placement: size error %, shape error mm, worst single corner, where the board was, and how far from the setup spot.
- Ends with a summary.

**Output:** a folder `validate_3d_<date>_<time>` inside the recording folder, containing:
- `report.txt`, exactly what was printed;
- `report.json`, every number;
- `placements.csv`, one row per placement;
- `placement_NN_<serial>.png`, each camera's frame with the measured corners (green circles) over the detected ones (red dots).

## 3. What to send back

Upload the `validate_3d_*` folder. If the script could not run, upload the whole recording folder instead (videos, `_metadata.csv`, `_events.jsonl`, `_segments.csv` and `_calibration.json` of both cameras).

## Reading the numbers

- **Size error:** how much bigger or smaller the board measures than it really is. 1% of a 20 cm hand span is 2 mm.
- **Shape RMS:** how far, on average, the measured corners are from a perfect board after the best fit.
- **Worst corner:** the largest single-corner error.
- **The placement at the setup spot always looks good,** because the setup was fitted there. The placements far from it show the real accuracy.
- **No placements found:** the board was not still for 2 s in both views, or a hand was in front of it. `--min-static-s 1.5` accepts shorter stills.
